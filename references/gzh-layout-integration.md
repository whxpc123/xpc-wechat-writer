# gzh-design 排版集成

本 Skill 使用独立的 `gzh-design` Skill 完成公众号正文排版，不复制其主题源码。上游项目：<https://github.com/isjiamu/gzh-design-skill>。

## 定位依赖

先运行：

```bash
node <xpc-skill-dir>/scripts/resolve_gzh_design.mjs
```

脚本会依次查找显式环境变量、当前项目和全局 Skill 目录。找到后，完整阅读返回目录中的 `SKILL.md`，再按其要求读取主题索引、选中的主题组件库和通用组件库。

若未找到，停止排版并向用户说明需要安装：

```bash
npx -y skills@latest add isjiamu/gzh-design-skill \
  --skill gzh-design \
  --agent codex \
  --global \
  --copy \
  --yes
```

不要在缺少组件库时凭记忆仿写主题 HTML，也不要静默退回旧的 `modern + blue` 排版。

## 主题选择

正式大纲中增加「排版主题」小节，列出一个推荐项和全部可选主题：

| 主题 | 适合内容 |
|---|---|
| 摸鱼绿 | 教程、清单、方法论、数据密集文章 |
| 红白色系 | 深度分析、观点和力量感话题 |
| 石墨极简风 | 科技评论、专业观点和高端质感 |
| 留白禅意风 | 深度随笔、生活与艺术话题 |
| 摸鱼票据风 | 工具对比、调查实验和创意评测 |
| 橄榄手记 | 案例复盘、系统说明和内刊手记 |

选择规则：

- 用户指定主题时直接使用。
- 用户只确认大纲、没有指定主题时，使用正式大纲中标出的推荐项。
- 用户说「按推荐主题」「直接排」「不用问」时，自动使用推荐项。
- 用户单独要求给现成文章排版且未指定主题时，先推荐并让用户选择；若同一句明确说「按推荐主题」，不再询问。
- 排版主题是可选配置，不新增强制确认点。用户可以用「确认大纲，排版用石墨极简风」一次完成大纲确认和主题选择。

最终选择写入文章目录的 `spec.md`，不要跨文章继承上一次的主题。

## 输入与产物

1. 把完成去 AI 味和事实终审的 `article.md` 复制或整理为 `article-formatted.md`。
2. 使用选定主题生成纯公众号正文片段，保存为 `article-formatted.html`。
3. `article-formatted.html` 必须以单个根 `<section>` 开始并结束，不含 `doctype`、`html`、`head`、`body`、`style` 或 `script`。
4. 保留全部正文、链接和图片；提示词使用代码块组件；不添加作者名、卡兹克署名、投稿邮箱或虚构经历。
5. 额外保留带主题名的副本：`article_排版_{主题中文名}({英文标识}).html`，方便人工识别。
6. 运行上游 `scripts/validate_gzh_html.py article-formatted.html`，必须达到 0 ERROR、0 WARNING。
7. 再运行本 Skill 的 `build_publish.mjs`，把纯正文接入四按钮复制工作台。

## XPC 长期规则优先级

主题组件库若要求作者签名或默认作者占位，XPC 文章一律省略该签名。允许保留通用点赞、在看、转发提示，但不得出现作者姓名、联系邮箱或投稿信息。

封面仍使用文章目录中的 `imgs/cover.png`，保持 1800 × 766、2.35:1；正文主题中的视觉封面组件只是正文开场模块，不替代公众号外部封面。
